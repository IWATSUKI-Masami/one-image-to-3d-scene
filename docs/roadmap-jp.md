# 今後の拡張

[English](roadmap.md)

今後の拡張の予定です。以下の内容は 2026年11月時点で確認したものです。

## 実装済み

以前のロードマップにあった項目のうち、アプリに入ったものです（使い方は README を参照）。

- **遠近を考慮した配置**：**Perspective** チェックボックスで、点群、PC Box、モデルをピンホールカメラから3次元に戻し、手前の物体が拡大されすぎないようにします。残っている仮定は5番。
- **一部しか写っていない物体の配置**（3番）：写真上の物体マスク（ブラウザ内の SAM 2.1）、見えていた部分を補完画像の中で既知の枠に保つ補完（特徴点マッチングが不要）、その枠を使った論文の箱による配置。サンプルの画像の端の椅子が、人物の後ろに置かれるようになりました。
- **向き**（4番）：向き合わせで、各モデルの正面の姿を補完画像に合わせ（描画して比べる）、さらに視線方向の角度だけ回します。サンプルの2人は向かい合います。
- **人物の顔**（6番、一部）：補完のオプション **Face**（既定は Calm）と、人物の3D生成の解像度の引き上げ。

開発中に試して削除したもの：Orient Anything による向きの推定（向き合わせに置き換え）と、一部しか写っていない物体の位置・大きさ・向きを描画して探す当てはめ（保った枠による箱の配置の方が良い結果だった）。

## 1. 3D生成への Pixal3D の追加（Hugging Face Space）

[Pixal3D](https://huggingface.co/TencentARC/Pixal3D)（Tencent ARC、SIGGRAPH 2026、MIT ライセンス）は、PBR テクスチャ付きのメッシュ（GLB）を出力する画像-to-3D モデルです。

### このシステムに合う理由

多くの3D生成モデルは、形状を独自の座標空間で作るため、画像の画素と3Dモデルの対応があいまいになります。Pixal3D は **ピクセル整合生成** を採用しています。MoGe で推定したカメラの画角を使って画素を3Dに逆投影するため、**生成されたモデルの正面が入力画像と1対1で一致します**。

このシステムでは、補完画像の中で見えていた部分（補完の間保った枠）と物体全体（tightBox2d）が PC Box に対応するように、モデルの拡大率と位置を決めています（論文の 3.5.3 節）。生成モデルの縦軸まわりの回転は、向き合わせ（4番）で補正できるようになりましたが、モデルの正面と画像のそれ以外の違い（比率、傾き）は残ります。ピクセル整合のモデルなら、この対応が正確になります。

### 実現方法

- 公式 Space [TencentARC/Pixal3D](https://huggingface.co/spaces/TencentARC/Pixal3D) が ZeroGPU で稼働しており、`preprocess`、`generate_3d`、`extract_glb_api` の API を公開しています。TRELLIS.2 と同じ構成なので、同じ方法で追加できます（手元の GPU は不要）。
- 実装時に確認すること：`generate_3d` のパラメータ、シーン内でのモデルの向き、tightBox2d との位置合わせ。

### 点群への当てはめ

Pixal3D を点群との位置合わせと組み合わせれば、位置・向き・大きさをまとめて決められる可能性があります。

1. **Pixal3D で初期の姿勢を得る**：モデルが入力画像のカメラの座標で生成されるなら、カメラに対する向きは最初から合っており、向き合わせ（4番）は要らない。
2. **見える面を取り出す**：そのカメラから見えるモデルの面を取り出す。
3. **位置合わせ**：その面を、物体のマスク内の点群（深度マップから作るもの）に、拡大率を含めて当てはめる（ICP / Umeyama 法）。位置、大きさ、向きの微調整が一度に決まる。ICP は初期の向きが大きくずれていると失敗しやすいが、Pixal3D なら良い初期値が得られる。見えている面どうしを合わせるので、一部しか写っていない物体（3番）にも効く可能性がある。

最初に確認すること：

- 出力の GLB がカメラの座標のままか、大きさと位置が正規化されるか。
- 入力は元の写真ではなく、補完した切り出し画像である。位置を保つ補完で見えていた部分は既知の枠に残るので、写真の中の切り出しの位置と合わせて、カメラの変換を計算できる。
- 点群の精度は、5番の仮定（画角、遠/近の比）に左右される。

## 2. ComfyUI によるローカルでの3D生成

3D生成の選択肢として、Hugging Face Spaces に加えて **ComfyUI（ローカル）** を追加します。多くの利用者は適した GPU を持っていないため、既定は Spaces のままとします。

### 目的

- **ZeroGPU の利用上限や Hugging Face トークンが不要**：利用者自身の GPU で生成するため、待ち時間も安定します。
- **再現性**：モデルとワークフローのバージョンを固定できるため、論文の再現実験に向いています。
- **プライバシー**：画像が利用者の PC の外に出ません。
- **モデルを足しやすい**：ワークフローのファイルを差し替えるだけで、モデルを切り替えられます。

### 候補のモデル

ComfyUI の公式ドキュメントで確認した内容です。

| モデル | ComfyUI での扱い | 出力 | このアプリとの相性 |
|---|---|---|---|
| Pixal3D | 本体のノードで動く。テンプレート「Pixal3D & TRELLIS.2: Image to Model」 | PBR テクスチャ付きメッシュ（GLB） | 良い（1 を参照） |
| TRELLIS.2 | 本体のノードで動く。上と同じテンプレートで `Boolean (Switch to Trellis2)` により切り替え | PBR テクスチャ付きメッシュ（GLB） | 良い |
| Hunyuan3D 2.0 / 2.1 | 本体のノードは **形状のみ（テクスチャなし）** | メッシュ（GLB） | テクスチャ付き GLB を返す Hunyuan3D-2.1 の Space の方が良い |
| TripoSplat | 本体のノードで動く | **ガウシアンスプラット**。オプションの `SplatToMesh` で GLB に変換可能 | 優先度は低い（下記） |

このアプリは、モデルを GLB のメッシュとして読み込みます。そして、メッシュのバウンディングボックスから PC Box に合わせた拡大率と奥行きのずれを計算し（論文の式(10)(11)）、シーンを glTF/GLB で書き出します。TripoSplat の主な出力であるガウシアンスプラットは、この仕組みに合いません。オプションのメッシュ変換で GLB にはできますが、変換したメッシュが、最初からメッシュを生成するモデル（Pixal3D、TRELLIS.2）を上回る可能性は低いと考えます。

### 設計の概要

- 設定：ComfyUI のアドレス（既定 `http://127.0.0.1:8188`）と、**API 形式**のワークフローファイル（ComfyUI から書き出したもの）。
- Pixal3D / TRELLIS.2 のワークフローをリポジトリに同梱する。
- 呼び出しの流れ（ComfyUI の HTTP API）：
  1. `POST /upload/image`：補完・背景除去済みの画像をアップロード
  2. `POST /prompt`：`LoadImage` ノードにアップロードしたファイル名を入れて、ワークフローを送信
  3. `GET /history/{prompt_id}`：処理が終わるまで状態を確認
  4. `GET /view?filename=…`：保存ノードが出力した GLB をダウンロード
- Pixal3D のワークフローには背景除去（BiRefNet）が含まれており、スイッチで省略できる。このアプリの入力は背景除去済みなので省略する。
- 配置の処理は今のものを使い回す。モデルの向きはワークフローごとに設定する。

### 制約

- **NVIDIA の GPU が必要**：VRAM の目安は、Hunyuan3D 2.0 で約 6〜12GB（形状のみ／形状＋テクスチャ）、TRELLIS.2 で約 24GB（第三者のガイドによる推奨値）。Pixal3D のページには記載がない。
- **モデルのダウンロード**：Pixal3D には、本体の拡散モデルに加えて、TRELLIS.2 の形状・テクスチャ用 VAE、DINOv3、MoGe、BiRefNet が必要。
- **ブラウザからの接続**：アプリがブラウザから呼び出せるように、ComfyUI を `--enable-cors-header` 付きで起動する必要がある。
- **保守**：ComfyUI の更新でノード名が変わると、ワークフローのファイルを直す必要がある。
- **テスト**：GPU のある環境が必要（CPU だけの環境では確認できない）。

## 3. 一部しか写っていない物体の配置

### 状況

ほぼ解決しました（「実装済み」を参照）。以前は、一部しか写っていない物体がかなり小さく配置されていました。補完で生成AIが物体全体を描き直すため、特徴点マッチング（AKAZE）で見えていた部分を見つけられず、物体全体のモデルがその小さな枠に押し込まれていたためです。今は、見えていた部分を補完の間、既知の枠に保ちます。

1. **物体のマスク**（**Segment Objects**）：検出した枠をプロンプトにして、ブラウザ内で SAM 2.1 を動かす。
2. **キャンバス**：VLM が写真全体を見て、物体が枠の外へ各方向にどこまで続くかを推定し、その余白を取って、画像生成AIの出力と同じ大きさのキャンバスに切り出し画像を置く。物体の画素だけを描き、OpenAI の編集マスクで固定する。物体を示した写真全体を参考画像として渡す。
3. **確認**：見えていた部分を枠の近くで相関により探す（小さなずれや大きさの変化は補正）。大きく動いた場合は補完をやり直し、AKAZE を予備として残す。
4. **向き合わせ**（4番）：モデルの正面の姿を補完画像に合わせるので、見えていた部分の枠がモデルの正しい部分に対応する。

### 残る課題

- **模様の少ないごく一部しか見えない物体**：サンプルのテーブルは天板の手前しか見えず、位置はまだおおよそ。その枠からは、テーブルの残りがどこにあるかがほとんど分からない。
- **案**：床への接地（家具は床に立つ。床の高さは人物の足元から推定）、人物との比率による一般的な大きさ、ピクセル整合の生成（Pixal3D、1番）と点群への当てはめ。
- **評価**：一部しか写っていない物体を含む複数の写真で、同じ設定で確かめ、サンプルだけに合わせないようにする。

## 4. 向き

### 状況

向き合わせとして実装しました（`services/frontAlignment.ts`）。各モデルを縦軸まわりに回して描画し、補完画像と比べ（シルエットの IoU、縦横比、明暗の相関）、最もよく一致する角度に回します。遠近を考慮した配置では、さらに視線方向の角度だけ回します。正解の角度が分かっている描画では、椅子を 3° 以内、カップを約 12° 以内で当てました。Orient Anything による最初の版は、これに置き換えました。

### 残る課題

- **対称に近い物体の前後・左右の取り違え**（カップ、花瓶、横から見た人物など）：反対の角度のシルエットがほぼ同じになる。今は、回す角度が小さい方をわずかに優先し、生成されたままの向きを保つ。明暗や色の特徴の重みを増やす、VLM に「モデルは画像と同じ向きか」を確認させる、物体の対称性も推定する **Orient Anything V2**（[Space](https://huggingface.co/spaces/Viglong/Orient-Anything-V2)）を使う、などで解決できる可能性がある。
- **縦軸以外の回転**（傾いた物体）は扱っていない。

## 5. カメラと深度の較正

遠近を考慮した配置（上の「実装済み」を参照）は、まだ2つの仮定に頼っています。

- **画角**：水平画角を 60° と仮定しています。EXIF から読むか、カメラの内部パラメータを推定するモデル（MoGe など）で求められます。
- **遠/近の距離の比**：Depth Anything V2 の相対的な視差は画像ごとに全範囲に引き伸ばされるので、比が分からず、Depth スライダーで設定しています（既定 1.5。サンプル写真で調整）。メトリック深度のモデル（Depth Anything V2 Metric、Depth Pro、MoGe など）を使えば実際の距離が得られます。シーン内の物体の一般的な大きさ（カップ、人物の頭など）から比を推定する方法もあります。

向き合わせの視線方向の補正も同じ画角を使っているので、こちらの精度も上がります。

## 6. 人物の顔の改善

### 状況

一部を実装しました（「実装済み」を参照）。人物の3Dモデルの顔が不自然（不気味）に見えていました。補完した全身の画像（1024×1536）では顔が数十ピクセル分しかなく、汎用の画像から3Dを作るモデル（TRELLIS.2、Hunyuan3D-2.1）はその大きさでは顔の凹凸を作れず、のっぺりした形に目鼻を描いたような見た目になっていたためです。

- **実装済み**：補完のオプション **Face**（**Calm**（既定。顔をくっきり描き口を閉じる。開いた口や歯が不気味に見えたため）、**Redraw**、**Mannequin**（目鼻を描かない）、**As in photo**）と、人物の解像度の引き上げ（TRELLIS.2 は 1536・テクスチャ 4096、Hunyuan3D-2.1 は Octree 384）。顔はかなり良くなったが、まだ完全には自然でない。

### 残る課題

- **3D生成の前に顔を補正する**：顔補正のモデル（CodeFormer など）の Space で、補完した画像の顔をくっきりさせる。
- **人物専用の3D生成モデル**（PSHuman、LHM など、人体のモデルを使うもの）：品質は最も良いが、Space として使えるか、ライセンスはどうかの確認が必要。
