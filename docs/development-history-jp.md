# プロジェクト開発履歴: 3D Scene Reconstruction from One Image

本ドキュメントは、3D Scene Reconstruction from One Image アプリケーションの開発タイムラインとユーザー要件をまとめたものです。

## フェーズ1: コアな物体検出とクロッピング
1.  **初期セットアップ**: 1枚の画像に対して物体検出を行い、検出した各物体をバウンディングボックスで切り出すアプリケーションを作成。
2.  **精度向上**: クロッピングの精度を改善。初期の切り出しは十分に正確ではなかった。
    *   *対応*: `gemini-3-pro-preview` に切り替え、プロンプトを「タイトな」バウンディングボックスを要求する形に調整し、フラッシュカットのためにパディングを削除。
3.  **物体の分離問題**: 花瓶と花が別々に切り出されてしまう問題に対処。
    *   *対応*: 物理的につながっている関連アイテムを1つのバウンディングボックスにまとめるよう、プロンプトを調整。
4.  **一貫性**: 実行のたびに結果が変動。
    *   *対応*: API の temperature を 0 に設定し、seed を固定。

## フェーズ2: 背景除去
5.  **機能要望**: 背景を除去するボタンを追加し、結果を別タブで表示。
6.  **実装試行**:
    *   *試行1*: `@imgly/background-removal`（クライアントサイド）を使用。環境における CDN/Wasm の読み込み問題で失敗。
    *   *試行2*: Gemini ベースのセグメンテーションマスク（Polygon/SVG）を試行。結果は「破綻」または低品質画像に。
    *   *最終解*: **Remove.bg API** を統合。API キー入力とバッチ処理ロジックを追加。
7.  **洗練**:
    *   **エラーハンドリング**: 画像を Base64 ではなく Blob として送信することで 400 エラーを解消。
    *   **細い物体**: 木製の椅子が消えてしまう問題。
        *   *修正*: パディング調整を試行（のちに元に戻す）。API に `type` ヒント（'person' と 'object'）を状況に応じて送るロジックを実装。
    *   **スマート抽出**: 通常の背景除去が失敗する難ケース（重なり合う物体など）に対応するため、Gemini ベースの「スマート抽出」機能を追加。

## フェーズ3: 分類と画像補完
8.  **分類**: ラベル（例: "Woman in yellow sweater"）に基づき、検出アイテムを自動で「Person」または「Object」に分類。
    *   *UI*: 「すべて」または「人物のみ」を表示するフィルタを追加。
9.  **直接アップロード**: すでにクロップ済みの画像を直接アップロードして背景除去を行う機能（バッチモード）を追加。検出ステップをスキップ。
10. **全身生成（アウトペインティング）**:
    *   `gemini-3-pro-image-preview` を用いて切り抜かれたポートレートの欠落した下半身を生成。
    *   *制約*: 人物生成時は家具（椅子・テーブル）や背景を厳密に除去。
11. **物体補完**: 一般物体にも生成を拡張（花瓶の切れた縁を修復など）。
    *   *UI*: ターゲット種別（Person/Object）切替トグルを追加。
    *   *管理*: AI 生成アセットを管理する「Completed」タブを追加し、削除機能を実装。
12. **トリミング**: 処理後画像の透明エッジを自動トリミングする機能を追加。

## フェーズ4: 3D モデル生成
13. **Stability AI 連携**: 「Completed」画像を Stability AI の API で 3D モデル（GLB）に変換する機能を追加。
    *   *UI*: `<model-viewer>` を用いた 3D プレビューカードを追加。
    *   *フロー*: ランディングページに独立した「3D 生成」モードを追加。

## フェーズ5: 3D シーン再構築
14. **コンセプト**: 元の 2D 画像に基づき、生成したモデルを相対位置で配置して 3D シーンを再構築。
15. **実装（Three.js）**:
    *   CSS 配置からフル **Three.js** キャンバス環境へ移行。
    *   **アンプロジェクション**: 2D バウンディングボックス座標 $(u, v)$ を 3D 空間 $(X, Y, Z)$ に変換する数式を実装。
16. **改良とフィジックス**:
    *   **フォグ**: 遠方のオブジェクトが消えないようフォグ距離を調整。
    *   **座標系**: 左右の反転（Left/Right）と奥行の反転（Front/Back）を修正。
    *   **スケーリング**: カメラからの距離に基づき GLB モデルを正しくスケールする「Measure & Fit」ロジックを実装。
    *   **グラウンディング**: 3D の床高を計算し、モデル底面を合わせることでオブジェクトが床に沈む問題を修正。
    *   **相対配置**: テーブル上のオブジェクトに対応。画像の $Y$ 座標に基づいて垂直位置を計算し、シーンをアンカーして人物が床（$Y=0$）に接するように調整。
    *   **傾き**: `lookAt()` の代わりに `Math.atan2` を用いた Y 軸回転を明示的に適用し、前傾する問題を修正。
17. **奥行き推定**:
    *   **ヒューリスティック**: 初期実装では垂直位置（$Y$）から奥行きを推定。
    *   **深度マップ**: より正確な Z 位置決定のため、Hugging Face API（`@gradio/client`）経由で **Depth Anything V2** を統合し、実際の深度マップを取得。
    *   **ハイブリッドロジック**: 2D 画像で人物の足より高い位置にあるオブジェクトはテーブルトップ上にあるとみなし、深度マップの値を上書きして花瓶が床に沈まないよう補正。

## フェーズ6: インフラと UX
18. **リブランディング**: アプリケーション名を **「SceneCraft AI」** に変更。
19. **プロジェクトアーカイブ**: ワークフロー全体（画像・モデル・メタデータ）を JSON に永続化する **保存/読み込み** 機能を追加し、API クレジットの節約を実現。
    *   *詳細*: ファイル名にフェーズ指標を含める（例: `phase1-2-4`）。
20. **バグ修正**:
    *   インポートマップ内の Three.js バージョン競合により発生した 3D シーンの「ブラックスクリーン」問題を修正。
    *   Canvas データ操作に関する CORS 問題を修正。

## フェーズ7: 洗練と最適化（v1.1.0）
21. **3Dオブジェクト配置の高度化**:
    *   **アンカーベース配置**: 画像内の垂直位置とオブジェクトタイプ（地面設置 vs 卓上）を組み合わせた配置ロジックを実装。
    *   **AI補完の考慮**: 生成された3Dモデルが元のバウンディングボックスよりも拡張されている（例：人物の下半身補完）ことを考慮し、配置基準点を調整。
    *   **卓上オブジェクト**: 卓上と判定されたオブジェクトの高さを統一し、浮遊や沈み込みを防止。
22. **自動スケーリング**:
    *   **深度分散分析**: 深度マップの分散とレンジを計算し、オブジェクトの3D的な厚みを推定。
    *   **動的補正**: オブジェクトタイプごとの基本スケールと深度分散を組み合わせ、より自然なサイズ感を実現（特に小物が小さくなりすぎる問題を解消）。
23. **保存機能の完全化**:
    *   **深度マップとシーン設定の永続化**: 生成された深度マップと3Dシーンの状態をプロジェクトファイルに含めることで、読み込み時の再生成（API消費）を不要に。
24. **API制限対策とセキュリティ**:
    *   **Hugging Face Token対応**: ZeroGPUクォータ制限を回避するため、トークン入力機能を追加。
    *   **環境変数**: `.env.local` によるセキュアなAPIキー管理に対応。
25. **UX改善**:
    *   **3Dモデルの向き**: 初期表示でモデルが正面を向くようにカメラ軌道を修正。
    *   **奥行き調整**: シーン全体の奥行き感を調整できるスライダーを追加。

## フェーズ8: 3Dバウンディングボックスと可視化の改善 (v1.2.0)
26. **3Dバウンディングボックス計算**:
    *   **ピンホールカメラモデル**: ピンホールカメラモデルを使用した厳密な3Dバウンディングボックス計算を実装。
    *   **深度サンプリング**: 背景除去済み画像の透明でないピクセルのみから深度をサンプリングし、中央値を使用して正確な3D配置を実現。
    *   **アンプロジェクション**: 2D画像座標と深度値を正確な3Dワールド座標に変換。
27. **可視化の整理**:
    *   **青いバウンディングボックスの削除**: 計算された3Dバウンディングボックス（シアン/青のボックス）のデバッグ表示を削除し、ビューを整理。
    *   **投影ボックスの維持**: 元の画像の3D空間内でのフットプリントを示す黄色の「投影2Dバウンディングボックス」表示は維持。
28. **UIとUXの更新**:
    *   **英語UI**: シーン再構築コンポーネント内のすべてのUIテキストを英語に統一。
    *   **デフォルト深度スケール**: 初期のシーン構成をより自然にするため、デフォルトの深度スケールを `0.3` に更新。

## フェーズ9: ワークフロー最適化とモデルビューアー改善 (v1.3.0)
29. **Extractedタブからのバッチ完了**:
    *   **直接完了**: Extractedタブから直接、背景除去ステップを完全にスキップして画像を一括完了する機能を追加。
    *   **API効率化**: 背景除去が不要な場合、切り取られた画像からAI完了画像に直接移行できるようにし、API呼び出しを削減。
    *   **UI追加**: Extractedタブのアクションバーに「Complete All」/「Complete (N)」ボタンを追加。
30. **自動タブナビゲーション**:
    *   **即時フィードバック**: すべてのバッチアクションボタンがクリック時に自動的に関連タブに切り替わるように:
        - 「Complete」ボタン → 「Completed」タブに切り替え
        - 「Generate 3D」ボタン → 「3D Models」タブに切り替え
        - 「Generate 3D Scene」ボタン → 「3D Scene」タブに切り替え
    *   **UX改善**: ユーザーが元のタブで待つのではなく、即座に処理フィードバックを確認できるように。
31. **3Dモデルビューアーの修正**:
    *   **カメラ位置調整**: 3Dモデルが適切に中央配置され、ビューアー内で表示されるようにカメラのターゲットと軌道設定を修正。
    *   **正しい向き**: カメラを180度回転させ、モデルを背面ではなく正面から表示するように修正。
    *   **可視性設定**: 一貫したレンダリングのため、`<model-viewer>`に`camera-target`、`field-of-view`、`exposure`属性を追加。
    *   **自動フレーミング**: `camera-orbit="180deg 75deg auto"`を使用して、モデルサイズに基づく自動カメラ距離調整を実装。

## フェーズ10: 堅牢な背景除去とフォールバック (v1.4.0)
32. **Nano Banana Pro (Gemini)**:
    *   **直接透明化**: Gemini 1.5 Pro (`gemini-3-pro-image-preview`) を活用し、外部の背景除去APIを使用せずに直接透明背景の画像を生成。
    *   **プロンプトエンジニアリング**:
        *   *透明度*: 「濃いグレー」のアーティファクトを防ぐため、「完全な透明（Alpha=0）」を強制。
        *   *タイトなクロップ*: 出力オブジェクトがキャンバスに対して小さすぎる問題を解決するため、「タイトなクロップ」を要求。
        *   *影なし*: クリーンなスプライトを確保するため、すべての影の除去を明示的に要求。
33. **エラーハンドリングと回復力**:
    *   **クォータ管理**: レート制限とフォールバックを実装することで、Geminiからの `429 Too Many Requests` に対処。
    *   **サービス可用性**: プロキシターゲットの更新とフォールバック戦略の実装により、Hugging Faceモデルからの `410 Gone` エラーに対処。
    *   **フォールバック戦略**: プライマリサービスが失敗した場合でも機能を維持するため、多層的なアプローチ（Gemini -> ローカル/Hugging Face -> Remove.bg）を設計。

## フェーズ11: 高忠実度3D生成と高精度アライメント (v1.5.0)
34. **Stable Fast 3D統合 (Gradio)**:
    *   **移行**: 廃止されたStability AI APIを、Hugging Face Gradio Client経由の `stabilityai/stable-fast-3d` に置き換えました。
    *   **品質**: アプリケーションから直接、格段に高い忠実度の3Dモデル (GLB) 生成を実現しました。
35. **高精度オブジェクトアライメント (AKAZE)**:
    *   **特徴点マッチング**: OpenCV.jsを用いた **AKAZE** (Accelerated-KAZE) 特徴点マッチングを実装し、処理されたオブジェクトの元画像内での正確な位置を特定します。
    *   **フォールバック機構**: マッチング数が不十分な場合のための **SSD** (Sum of Squared Differences) フォールバックを追加しました。
    *   **結果**: 背景除去や補完が行われた「処理済み」オブジェクトが元の位置に完全に吸着し、3D空間での整合性が保たれます。
36. **インフラとUXの洗練**:
    *   **表示修正**: コンテナのアスペクト比の不一致によりバウンディングボックスのオーバーレイがずれる長年の問題を解決しました。`ResultCard` に動的コンテナシステムを実装しました。
    *   **CORS解決**: `model-viewer` のCDNをGoogle公式エンドポイントに切り替え、永続的なCORSおよび500エラーを解決しました。

## フェーズ12: 3Dシーンの洗練とUXの磨き込み (v1.6.0)
37. **3Dシーンの精度向上**:
    *   **距離スケーリング**: オブジェクトの厚みを増やす独自スケーリングを廃止し、「距離スケーリング」を導入しました。`depthScale` スライダーは、オブジェクトの形状を歪めることなく、Z位置（距離）を調整して深度感を強調するようになりました。
    *   **垂直方向の安定性**: 深度を調整するとオブジェクトが浮いたり沈んだりする問題を修正しました。距離スケーリングに関わらず、オブジェクトは常に床面（$Y=0$）に接地したままとなります。
    *   **正しい向き**: すべてのモデルがデフォルトでカメラに向くように（180度回転）、GLBモデルの読み込みロジックを修正しました。
    *   **高精度サンプリング**: 深度サンプリングのロジックを全面改善し、背景除去済み画像の透明でないピクセル（alpha > 128）のみから深度を収集。全ピクセルの中央値を使用することで、背景の影響を受けない正確な深度推定が可能に。
38. **インタラクティブなシーンフィルタリング**:
    *   **選択同期**: 「3D Models」タブで選択（チェック）されたモデルのみを3Dシーンに表示するフィルタリングシステムを実装しました。
    *   **リアルタイム更新**: モデルの選択を解除すると即座にシーンから削除されるため、構図の調整や不要なモデルの除外が容易になりました。
    *   **空状態の修正**: タブ切り替え時に3Dシーンが空になってしまうバグを解決し、適切なデフォルト選択ロジック（選択がない場合は全表示など）を導入しました。
39. **UI/UXの強化**:
    *   **読み込みフィードバック**: 単一モデル生成時にも「3D Models」タブにはっきりと「Generating...」インジケーターを表示するようにし、処理中のユーザーの混乱を防ぎました。
    *   **スライダー設定**: より柔軟なシーンレイアウト制御のため、深度スケールスライダーの範囲を `0.5x - 10.0x`（デフォルト `1.0x`）に更新しました。

    *   **コンテナベースのアプローチ**: スケーリングと配置の際にメッシュと緑ボックスを整列させたまま保持するため、`THREE.Group` コンテナシステムを実装しました。

    *   **データ整合性**: すべての3Dモデルが正確な緑ボックスレンダリングのための適切なバウンディングボックスメタデータを持つことを保証します。

    *   **紫ボックスの削除**: ユーザーの要望に応じて、`DepthOnlyScene` から紫色（モデル全体）のバウンディングボックスを削除し、`originalPartBox2d` 用の緑ボックスのみを維持するようにしました。
